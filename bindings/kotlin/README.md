# yubtc Kotlin / UniFFI bindings

These files are generated by `uniffi-bindgen` from the `yubtc-core`
cdylib. **Do not edit by hand** — your changes will be overwritten.

## Regenerate

```sh
# 1. Build the cdylib for the host (debug is enough for binding generation)
cargo build -p yubtc-core --lib

# 2. Generate the bindings into bindings/kotlin/
uniffi-bindgen generate \
    --language kotlin \
    --out-dir bindings/kotlin \
    target/debug/libyubtc_core.so
```

## When to regenerate

- After adding/removing/renaming any `#[uniffi::export]` function,
  `#[derive(uniffi::Record)]` struct, or `#[uniffi::Enum]` variant in
  `core/src/uniffi_api.rs`.
- After bumping the `uniffi` crate version.
- After adding/removing the `#[uniffi::Error]` derive on a new error
  type.
- The CI `bindings` job (the `bindings` job in
  `.github/workflows/release.yml`) regenerates the bindings and
  fails the build if the checked-in copy is out of sync.

## Layout

```
bindings/kotlin/
└── uniffi/
    └── yubtc_core/
        └── yubtc_core.kt     # generated facade (Kotlin + JNA)
```

`yubtc_core.kt` is self-contained — it inlines the UniFFI runtime
helpers (RustBuffer, FfiConverter, UniffiLib) and depends only on
`com.sun.jna` (the Java Native Access library). No external UniFFI
runtime jar is required.

## API surface

See the public symbols in `yubtc_core.kt`:

- `WalletHandle` — opaque handle to a derived wallet; constructor
  takes `(seed, nonce, passphrase, kdf, backend)`.
- `AddressInfoRecord`, `TxResultRecord`, `UtxoRecord` — value types.
- `KdfAlgoName` — enum (`YUBTC`, `PBKDF2`, `ARGON2ID`, `SCRYPT`).
- `YubtcException` — error type mapped from `YubtcError` in Rust.
- `uniffiEnsureInitialized()` — must be called before any other
  foreign function; loads the cdylib via JNA.
- Top-level functions: `generateSeed`, `validateSeed`,
  `satoshiToBtc`, `btcToSatoshi`, `defaultConfirmations`,
  `defaultFeekbSat`, `minimalFeeSat`, `setBackend`.

The full FFI surface mirrors `core/src/uniffi_api.rs`.
